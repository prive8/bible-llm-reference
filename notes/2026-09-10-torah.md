### 2. Silent tradition-filter bug found and fixed

Caught while writing the new `--tradition judaism` choice in
`bible/semantic.py`:

- v0.8.0–v0.10.0 used `if filter_tradition not in entry_trad`
  (substring match), but stored entries use `tradition="christianity"`,
  not `"bible"`. So `--tradition bible` was silently returning 0 results.
- `--tradition all` had the same bug: `"all"` is not a substring of any
  stored tradition, so all entries got skipped.
- **Fix**: explicit alias map
  (`bible → christianity`, `muslim → islam`, `jewish → judaism`)
  + exact-match comparison, with explicit `all`/None = no filter.
- **Regression test**: `t_semantic_tradition_filter_aliases` covers all
  four code paths.

## Open question: when to actually index Torah for semantic search?

The adapter + tests are shipping without a real semantic index for the
Torah text. The next time someone runs `scripts/index_embeddings.py`,
Torah passages will be added to the corpus. That happens automatically
the next time `eval-regression` CI job runs (it rebuilds the index).

Estimated impact on eval: 33-query benchmark is Bible+Quran-only, so
those numbers don't change. Adding Torah pushes the corpus from 43K
passages to ~49K (Bible 37K + Quran 6K + Torah 5.8K). Index build time
goes from ~200s to ~225s on CPU. nDCG should be similar or slightly
better (more corpus = more chances to find relevant material).

## Decisions made

- **Sefaria as the source**, not eBible.org or Internet Archive directly.
  Sefaria's API gives both English and Hebrew in one call with consistent
  schema. The underlying texts (JPS 1917 + Miqra MAM) are independently
  re-hostable; if Sefaria ever dies we can re-ingest from upstream sources.
- **Hebrew-with-nikkud as the primary Hebrew edition**, not unpointed.
  Most users (including AIs) need vowel points to disambiguate. The
  unpointed version is one Sefaria flag away if needed later.
- **No Targum Onkelos / Rashi in v0.11.0.** Those are commentary, not
  base text. Phase 3.3+ if wanted.
