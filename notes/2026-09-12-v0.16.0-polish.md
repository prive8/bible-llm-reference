## Decisions made
- **`-n` alias for `--top-k` in `bible hybrid` is ergonomics only.** No semantic
  change. `-n` and `--top-k` are interchangeable; both forms now work in the
  CLI. The regression test guards against accidentally removing the long form.
- **`bible.__version__` follows `pyproject.toml`, not the other way around.**
  The `t_version_matches_pyproject_toml` regression test pins this direction;
  if someone updates `bible/__init__.py` first, the test fails until
  `pyproject.toml` is also bumped. Source of truth = `pyproject.toml [project]
  version`.
- **v0.16.0 is a polish release, not a milestone.** No new capability; just
  CLI consistency + version drift fix. Phase 4 MVP is the next milestone after
  this polish release.
- **Phase 4 MVP scope is documented but not implemented.** The scope doc
  (`docs/phase4-scope-frontend.md`) is the cold-start anchor for the next
  agent who picks up the front-end work.
- **Reader layer ships first because Sarah is the load-bearing persona.**
  A feature that confuses Sarah is a blocker; a feature that confuses Aisha
  is missing but not blocking.
- **The MVP backend work is glue + tests + docs, not new engineering.**
  The data + retrieval substrate is mature (v0.15.0).
