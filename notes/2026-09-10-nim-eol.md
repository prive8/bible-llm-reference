# 2026-09-10 — Torah data ingest + NIM EOL discovery (v0.11.0 followups)

## Done

### 1. Torah data ingest complete (Option 1 closeout)

Two editions written to `data/torah/` (commits `360604f`):
- `hebrew-nikkud.json`: 5846 verses of תנ״ך עם ניקוד (Public Domain via tanach.us)
- `jps1917-modernized.json`: 5846 verses of Modernized Tanakh (CC-BY Adam Cohn)

Total expected: 5852. Gap: 6 verses missing on both editions — likely a
Sefaria feed quirk (possibly merged verses or psalms-style intentionally
omitted verses). Same gap on both sides confirms it's a source issue,
not an ingest bug. Acceptable for retrieval.

**Heads-up caught during ingest**: First run wrote English text into
`hebrew-nikkud.json` because `extract_hebrew()` was a stub that called
`extract_english()` — both read Sefaria's `text` key. Actual Hebrew
lives in `he` key. Fixed in scripts/ingest_torah.py and re-ran.

**Heads-up caught in test**: Sefaria's nikkud combining-mark ordering
is dagesh-before-sheva (canonical NFC). Manually-typed nikkud in test
code renders sheva-before-dagesh — Unicode treats these as different
strings. Test now strips combining marks before substring match.

### 2. NIM benchmark attempt — **gated behind paid tier** (Option 3 finding)

This is a real, surprising finding worth documenting before any further
attempt:

- The v0.7.0 default model `nvidia/nv-embedqa-e5-v5` returns **HTTP 410
  Gone** ("reached its end of life on 2026-08-25T09:00:00Z and is no
  longer available"). That's a model EOL, not a transient outage.
- 6 replacement NIM embedding models were tried via the live API; every
  one returned **`Function '<id>' not found for account '<user-account>'`**.
  The user's free-tier account doesn't have entitlements for any of the
  embedding models listed in `/v1/models`.
- `/v1/models` shows 80 models on the account (mostly chat), but
  **zero embedding models** are reachable.
- Same `Function not found for account` error for chat completions
  on a model that *is* in the list (`meta/llama-3.2-3b-instruct` — but
  that one also returns 410 Gone, separate issue).

**This means HANDOFF §8 #1 (operational NIM use) and #8 (NIM recall
ceiling) cannot be closed on free tier.** Both decisions remain open
until the user authorizes a paid NIM spend.
